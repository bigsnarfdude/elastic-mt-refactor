1. The 24-hour arc

The framing the whole day operated under: Tim's simulator is a circuit. Same mech-interp tools that work on neural nets — ablation, SAE on activations, surrogate models — should work on a hand-built biological sim where the mechanism is written in Python and you can read it. The day was a test of that framing.

2. What changed in the code

The refactor's design goal: make ablation possible without editing Tim's code. The clean ablation surface is one line:

# Want to ablate the collision decision?
import collision.decision
collision.decision.decide_outcome = lambda a1, a2, r: 'cross'
# Done. The simulator picks this up via late binding.
Lyapunov caveat (worth raising with Tim). S₂ trajectories are bit-identical for the first ~0.5 sim-hours, then diverge by ~1–3% due to floating-point amplification in the chaotic dynamics. Statistical equivalence holds (well within seed-to-seed variance, and the S₂ distribution over seeds is unchanged) but the bitstream isn't preserved. This is expected for a chaotic event-driven sim; the refactor preserves Tim's physics, not his bitstream.

What broke and how it was found

Coverage hole at exact angle boundaries. Tim's zip_cat has 13 angle-quadrant branches. When angle1 exactly equals a quadrant boundary, none of the branches match and the function silently defaults to 'cross'. Random floats almost never hit these, but if anything upstream snaps angles to a grid (or if a future seed happens to land there), the behavior changes. The refactor's decide_outcome uses a normalized incident-angle formulation that has no boundary holes; tests pin this explicitly.
Python early-binding trap. The first version of api.zip_cat_clean did from collision.decision import decide_outcome at module load. Monkey-patching collision.decision.decide_outcome later had no effect — the local name was already bound. Fixed by switching to collision.decision.decide_outcome(...) attribute access at call time. A test now enforces "patches actually take effect" so this can't regress silently.
deflect_on=False still crashes deeper. Tried to kill elastic deflection as an independent ablation. comparison_fns.region_traj.add_traj asserts no two trajectories share both angle and point — true when elasticity perturbs every trajectory, false when MTs go straight. Patched that assertion and the sim crashes one level deeper. This is the next refactor: separate trajectory ID from elastic-bend uniqueness. Not done in this 24h.

3. Findings, ranked by confidence

Confirmed · strong signal · n=4 seeds at 10h

Finding 1 — Zippering is a rate, not a value

Static S₂ at t=1h hides the signal. The real difference between conditions is in the slope of S₂ over time:

  • baseline: S₂ climbs 0.59 → 0.86 over 9 sim-hours. Monotonic, still rising.
  • no_zipper: Locks in at S₂ ≈ 0.57 within the first sim-hour and never moves. Flat trajectory for 9h.
  • always_catas: Plateaus at S₂ ≈ 0.70 with very low MT density (~220).

The +0.22 baseline-minus-no_zipper gap at 1h grows to +0.29 at 9h. Zippering's contribution isn't a constant — it compounds as density compounds.

Confirmed · macroscopic equivalence

Finding 2 — Zippering does two jobs: alignment AND density control

At 9 sim-hours, mean MT density is:

  • baseline: ~1713 (tripled from t=1h's 940)
  • no_zipper: ~360 (flat — no growth)
  • always_catas: ~221 (flat, very low)

Without zippering, MTs don't accumulate. Zippering keeps MTs alive long enough that more arrive, more collide, more align. The collision rule's biggest job isn't aligning MTs per se — it's letting them survive. always_cross in the early sweep had unbounded MT accumulation (no catastrophes → memory blew to 3 GB in 30 min); the collision rule is doing alignment AND density control via collision-induced catastrophe, sharing one code path.

Confirmed · n=10 seeds, unsupervised

Finding 3 — SAE rediscovers orientation as the natural feature axis

32-feature SAE trained on 148,114 per-region snapshots from 10 seeds. No supervision, no S₂ target. After training:

  • 32 of 32 features alive (zero dead features at n=10 seeds; at n=1 there were dead features).
  • Each feature is tuned to a preferred angle in [12°, 158°]. Effectively the SAE has reconstructed an angular tuning curve set.
  • Top feature correlation with cos(2Ω) = +0.47 (the natural angular order metric).

Interpretation: the model has no special knowledge of nematic order, only stacked (angles, lengths, mt_len, θ) tensors. The fact that orientation falls out as the dominant feature axis means S₂ is the right summary statistic — Tim's hand-designed order parameter aligns with what an unsupervised method finds.

Partial · functional equivalence, mechanism brittle

Finding 4 — A 99.2% surrogate breaks the sim; a gated version doesn't

Tiny MLP (1,446 parameters): inputs (angle1, angle2, r), output one of {zipper+, zipper-, cross, catas}. Trains in seconds, gets 99.2% top-1 accuracy on Tim's rule.

Drop-in replacement crashes immediately. The elastic-deflection module assumes bit-exact zipper geometry; the MLP doesn't reproduce that. This is a real finding about how brittle the simulator's modular boundaries are at the geometry level.

The gated workaround works. Run the MLP only for cross/catas decisions; keep Tim's deterministic zipper geometry for zipper+ / zipper-. End-to-end sim runs, and the final S₂ is identical to baseline (0.7774 vs 0.7774). This is the cleanest "the simulator is a circuit" result: you can swap in a learned component and the macroscopic order parameter is preserved, but only if you respect the geometry contract.
Open question · n=3 seeds running

Finding 5 (in progress) — Does the gated MLP reproduce the 10-hour trajectory?

Three gated_MLP seeds running on nigel right now (same overnight batch). The 1-hour result shows perfect match. Whether the trajectory shape matches over 10h — particularly the rate of S₂ growth — is the test. If it matches, we've established that the collision decision alone (a 1,446-param MLP) is enough to reproduce the macroscopic dynamics. If it doesn't, we've found a non-obvious coupling between the decision rule and the long-term dynamics that doesn't show up in the 1-hour snapshot.

5. What I got wrong (and fixed)

Honesty about a mid-day misread that propagated into the first version of LUNCH_NOTES_FOR_TIM and into a few intermediate writeups.

Yesterday's framing: "The S₂ floor (~0.56–0.70) comes from branched nucleation. accept_MT = 0.24 means 24% of new MTs nucleate at angles correlated to existing ones, contaminating S₂ at low density. Run accept_MT=0 as the proper control."
Corrected: In default BY-2 parameter sets, LDD_bool = False. That flag gates whether sample_angle (the branched-angle generator) ever runs. With it off, new MTs nucleate isotropically regardless of accept_MT. The branched-nucleation contamination story was wrong on its premise.

The S₂ floor is the right size for statistical bias of measuring nematic order on sparse MTs. With ~200 MTs in a region, the sample S₂ has a positive bias even under isotropic distributions because S₂ ≥ 0 always; finite-N averages of |cos(2Δθ)| don't cancel to zero. The always_catas S₂ of 0.70 at density 220 is consistent with that.

This changes the interpretation of two earlier claims:

  • "branched nucleation dominates S₂ in low-density conditions" — wrong. It's small-N estimator bias.
  • "run baseline_isotropic as the proper control" — was based on the wrong premise. The right control for the noise-floor question is to increase MT density at low alignment (e.g., higher nucleation rate + always_cross) and see if the floor drops. Tractable on nigel; not run yet.

The headline findings (zippering as rate, density compounding, SAE rediscovery, gated MLP equivalence) are unaffected by this correction. They were measured at the right level. The error was in the interpretation of the floor, not in the trajectories themselves.

6. Questions for Tim

  1. Refactor PR. Can I PR the refactor branch against your main? It's mathematically equivalent at the unit level and statistically equivalent end-to-end; nothing else in your code changes. Gives you a clean ablation testbed and gets the 300-line zip_cat down to three small modules. About a day of your time to review the physics.
  2. The catastrophe-source question. Right now r_c (spontaneous catastrophe) and collision-induced catastrophe share one code path. For clean ablation we'd want to tag the source of each catastrophe. Do these have the same biological meaning, or are they actually two different things? If different, that's the right modular boundary to introduce next.
  3. S₂ reporting convention. When you report S₂ in your thesis, do you also report MT density? The 9h overnight data shows S₂(baseline)=0.86 at density 1713 vs S₂(always_catas)=0.70 at density 220 — both look like "high alignment" if you only report S₂. For anyone using your S₂ as ground truth for cross-comparison with experiments, the density context seems load-bearing.
  4. Do you have 10-hour run pickles? The GH200 surrogate sweep would like real ground-truth trajectories from runs longer than the 1-hour sweeps in this work. Even one or two of your own 10h pickles would unblock the active-learning loop.
  5. The deflect_on=False coupling. The elastic-deflection ablation still crashes deeper than the assertion at comparison_fns.py:2957. Worth a 30-min look together to identify the second coupling — it's the next refactor target after the collision split.
  6. LDD_bool semantics. Just to confirm: in your default BY-2 parameter set, LDD_bool=False means branched nucleation is off entirely, and accept_MT is only consulted when LDD_bool=True? (This is the correction in §5; I want to make sure I'm reading the gate right.)
